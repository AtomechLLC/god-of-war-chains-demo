## Phase Goal (MVP user story)

**As a** Phase-6 particle runtime (and the developer wiring it), **I want to** query the game's real decoded particle / emitter / shape values from a JSON-dumpable `FxDb`, **so that** fire, sparks, and trails render from authentic GoW1 data instead of hand-tuned approximations.

This plan is slice-1 layer 2 of the decode order **MSH → PTC → FXC** (D-02): particle definitions (which reference shapes) are decoded before the emitters that reference them.
</phase_goal>

<objective>
Decode `PTC_*` particle-definition records into magic/slot/matrix/size/shapeRef + param region, covering the trail particles (BFT/BGT, standalone `.bin`) and the fire particles (flame3/flame6, in-WAD) that roadmap SC2 names, and populate `FxDb.ptc` — merging the standalone-only trail defs via the buildFxDb 3rd arg so the D-01 priority data actually enters the queryable FxDb.

Purpose: Particles carry the rates/lifetimes/sizes Phase-6 needs; they reference shapes by name (mostly runtime handles). Decoding them second (D-02) means the FXC slice can then link emitter→particle.
Output: `FxParse.parsePtc`, `buildFxDb` ptc-section population (WAD + standalone), and extended `test/fxdb.test.js` — green.
</objective>

Standalone .bin = a HEADERLESS record (no 32-B WAD header). Its file byte 0 IS the record magic, so synthesize a rec:
  { name, idx:0, tag:0x1e, size:file.length, dataOff:0 } and pass the whole file as buf.
  (05-PATTERNS "Standalone .bin = headerless record".)

PTC byte layout (VERIFIED first-party; RESEARCH "Record Structure → PTC", variable length 520-632):
  +0x00 u32 magic = 0x00000013   (constant across all 10 PTC read)
  +0x04 u32 0
  +0x08 u16 slot id              (matches the paired FXC +0x08)
  +0x0a u16 0xffff / index
  +0x10..0x4f f32[16] placement matrix (same convention as FXC; often identity)
  +0x50 u32 record size          (equals record length)
  +0x54 char[] NUL-terminated "…Shape" name
  +0x64.. f32[] params — lifetimes/rates/sizes as NTSC 60Hz ticks (D-05)
  tail: ASCII "1555" (bytes 31 35 35 35) — suspected A1R5G5B5 particle-texture-format tag (A1, INFERRED)

Seed values (byte-exact this session):
  PTC_flame3 (in-WAD @0xcd50): magic 0x13, size@0x50 632, name@0x54 "flame3Shape"
  PTC_flame6 (in-WAD @0xc890): magic 0x13, size 632, name "flame6Shape"
  PTC_BFTpart1 (standalone .bin, 568 B): magic 0x13, slot@0x08 0x1d, size 568, name "BFTpart1Shape"
  PTC_BGTpart1 (standalone .bin, 552 B): magic 0x13, slot 0x1d, size 552, name "BGTpart1Shape"
  IMPORTANT (Pitfall 4 / A3): the static RGBA region in PTC is identity (1,1,1) and byte-identical fire-vs-swoosh — DO NOT read a "color" from it.
