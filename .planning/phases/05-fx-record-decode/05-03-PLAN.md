FXC byte layout (VERIFIED first-party; RESEARCH "Record Structure → FXC"; layout after +0x50 BRANCHES on subtype — Pitfall 2):
  +0x00 u16 magic = 0x001e   (constant across all 9 FXC)
  +0x02 u16 subtype          0x2 emitter / 0x3 spark / 0xc grav / 0xd poly
  +0x04 u32 0
  +0x08 u16 slot/class id    (links FXC↔PTC — same id in the paired PTC)
  +0x0a u16 per-emitter index / 0xffff root sentinel
  +0x10..0x4f f32[16] 4×4 row-major placement matrix (rows orthonormal for a real rotation)
  +0x50 u32 record size (0xe4=228 for subtype 2/3; 0x88=136 for subtype 0xd)
  SUBTYPE 2/3: +0x54 char[] NUL-terminated particle/shape reference name
  SUBTYPE 0xd: +0x54 u32 count, then +0x58 char[] MSH name (the explicit FXC→MSH link)

Seed values (byte-exact this session):
  FXC_BFTemit1 (standalone .bin, 228 B): magic 0x1e, subtype 0x2, slot 0x1d, idx 0x05, size 228, ref@0x54 "BFTpart1Shape"; matrix row0 ≈ (0.00204, 0.75790, 0.65237)
  FXC_BGTemit1 (standalone .bin): IDENTICAL to BFTemit1 EXCEPT idx (0x06), name byte @0x55 (F→G → "BGTpart1Shape"), shape block. MATRIX IDENTICAL → fire & swoosh share placement.
  FXC_BDEsparkemit (in-WAD @0xcb70, 228 B): subtype 0x3, ref@0x54 "flame6Shape", matrix = identity (row0 = 1,0,0 — parent-origin)
  FXC_BDepoly3 (in-WAD @0xcc80, 136 B): subtype 0xd, u32@0x54 = 1, name@0x58 "MSH_BDepoly3Shape" → explicit FXC→MSH link
  NOTE (A4): BFT and BGT emit1 BOTH carry slot 0x1d — slot is a trail-position group id, not a fire/swoosh discriminator. The shapeRef NAME discriminates; slot is corroboration only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disc-derived bytes → parseFxc | Untrusted binary; subtype-branched offsets must not read a name past record end |
| shape-ref resolution | An unresolvable MSH_* target must fail loud, not silently produce a dangling ref |
| assets/ fetch policy | Reads stay under `assets/`; never widen to `extracted/` or ISO |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering / Info-disclosure | parseFxc short-record read | mitigate | Size-gate `rec.size < 0x58` before magic, throw naming the record; Task-1 (f) test |
| T-05-02 | Tampering | subtype-0xd name read at wrong offset (+0x54 vs +0x58) | mitigate | Branch on subtype BEFORE reading the name (Pitfall 2); known-answer per subtype; readName maxLen bounds the read |
| T-05-03 | Tampering | wrong same-name MSH copy resolved | mitigate | Resolve nearest-preceding from the FXC's idx (size>0, tag 0x70); throw on a true MSH_* miss |
| T-05-04 | Integrity (data-first) | dangling/fabricated cross-ref | mitigate | Only MSH_* refs marked resolved:true (via resolve); runtime handles marked resolved:false, never invented |
| T-05-SC | Tampering | supply chain | accept | Zero packages — node:assert + built-ins only |
</threat_model>
