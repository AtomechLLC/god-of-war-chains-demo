MSH_BDepoly3Shape byte layout (VERIFIED first-party this session; RESEARCH "Record Structure (MSH)"):
  +0x00 u32 vertCount   (=24 for the 768-B copy)
  +0x04 u32             (=22 — suspected index/strip count; record verbatim, tag INFERRED)
  +0x08 u32 0xffffffff  sentinel
  +0x0c u32 0xffffffff  sentinel

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disc-derived bytes → parseMsh | Untrusted binary record; a short/swapped record must fail loud, never read into the adjacent record |
| assets/ fetch policy | Reads stay under `assets/` (WAD only); never widen to `extracted/` or the ISO |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering / Info-disclosure | parseMsh short-record read | mitigate | Size-gate `rec.size < 0x10` BEFORE any field read, throw naming the record (WR-01); Task-1 short-MSH throw test pins it |
| T-05-02 | Tampering | parseMsh variable-length vertex walk | mitigate | Bound every vertex read by `dataOff + rec.size`; never assume a fixed length (Pitfall 3) |
| T-05-03 | Tampering | wrong same-name MSH copy (768 vs 1008) | mitigate | Callers/tests select via `Parsers.resolve` nearest-preceding (size>0, tag 0x70); Task-1 (b) asserts both copies |
| T-05-04 | Integrity (data-first) | fabricated decoded value | mitigate | Every field carries a real/INFERRED evidence tag; RED test pins byte-exact seeds; no color read from a shape |
| T-05-SC | Tampering | supply chain (npm/pip installs) | accept | Zero packages — node:assert + node built-ins only (CLAUDE.md); nothing to audit |
</threat_model>
